# Qualitative methods

Pick one primary design from the five. Write procedures that fit that design, not a generic "qualitative study." Worldview default: constructivist. Switch to transformative when the problem is oppression, inequity, or rights.

## Design fit

| Design | Unit | End product | Planned n (planning ranges, not fake counts) |
| --- | --- | --- | --- |
| Narrative | One or few lives | Story with chronology and context | 1–2 lives, multiple interviews each |
| Phenomenology | Shared lived experience | Description of the essence | 3–10 information-rich participants who have lived the phenomenon |
| Grounded theory | Process or action | Substantive theory with categories | ~20–30, theoretical sampling until category saturation |
| Ethnography | Culture-sharing group | Cultural portrait and patterns | One group; prolonged engagement; many artifacts and observations |
| Case study | Bounded case(s) | In-depth case description and themes | 1 case or 4–5 for a multiple-case study; bound the case in writing |

## Phenomenology procedure (when this is the design)

Use this sequence, not a generic theme list.

1. State the phenomenon in one phrase. Confirm every participant has lived it (criterion sample).
2. Researcher epoché / bracketing note — prior beliefs, employment, tool use, expected findings. For an agent, include search and coding bias (`references/writing-ethics.md`).
3. Data — primarily in-depth interviews (60–90 min), optional documents or artifacts the participant offers. Interview protocol from `assets/instruments.md`.
4. Analysis (Moustakas-style, name it):
   - horizonalization — significant statements
   - meaning units / clusters
   - textural description ("what" was experienced)
   - structural description ("how" the experience unfolded — context, conditions)
   - composite essence
5. End product is the essence, not five equally weighted "themes" that could fit any topic.
6. Trustworthiness: member checking of the essence if humans are involved; thick description; bracketing log; audit trail.

Do not run grounded-theory axial coding on a phenomenological question. Do not call a single interview a phenomenology.

## Researcher role and reflexivity

State access, prior relationship to the site or topic, expected bias, and how those will be recorded. For an agent, state that the "instrument" includes search policy, source selection, and coding rules. Keep a short bias log. Algorithmic-instrument threats are specified in `references/writing-ethics.md`.

## Data collection

Name types — interviews, observations, documents, audiovisual, artifacts. For each type:

- who or what
- how recruited or sampled (purposeful strategies — maximum variation, typical, snowball, criterion, theoretical)
- how recorded
- planned volume as a plan, not a fake completed count

Saturation is a stopping rule, not a slogan. Define what would count as saturation for this study (e.g. no new meaning units in two consecutive interviews for phenomenology; category completeness for grounded theory).

## Analysis (generic, then design-specific)

1. Organize and store raw materials.
2. Read for sense; write memos.
3. Code — in vivo and analytic. Do not pre-load a codebook unless the design is directed qualitative content analysis and you say so.
4. Build categories or themes. Themes need supporting excerpts.
5. Interpret against the questions, the literature, and the design's end product.
6. Represent — description, figures, theory diagram, case vignettes.

Design-specific extras

- Phenomenology — epoché; textural and structural description; essence (procedure above).
- Grounded theory — open / axial / selective or constructivist GT cycles; theoretical sampling; a theory statement with conditions, actions, and consequences.
- Ethnography — emic and etic; description of the group before analysis.
- Case study — case boundary statement; within-case then cross-case if multiple; multiple sources, not only interviews.
- Narrative — restorying; time, place, scene; collaboration with the storyteller when humans are involved.

## Trustworthiness (Lincoln and Guba terms as used by Creswell)

Plan at least three. Typical set:

- **Credibility** — triangulation of sources or methods, member checking if humans are involved, prolonged engagement or thick description of the corpus, negative-case analysis.
- **Transferability** — thick context so readers can judge fit. Not statistical generalization.
- **Dependability** — audit trail of coding decisions and protocol changes.
- **Confirmability** — reflexivity notes; separate excerpt from interpretation; optional external audit.

Peer debriefing and prolonged engagement are additional tactics when the site allows them. Do not invent participant quotes. If only documents exist, treat excerpts as documentary evidence and say so. That substitute is not phenomenology unless the documents are first-person accounts of the lived phenomenon and you say the limitation.

## Agent execution

Claim license: `references/inference-license.md`.

- Human interviews and field observation cannot be fabricated. Produce the protocol, guides, matrix, timeline, and a desk-research substitute only if the user accepts documents as the corpus.
- When the corpus is public text, code it. Show the codebook and enough excerpts to make themes inspectable.
- Refuse "10 themes" of equal weight. Report a small number of well-supported themes, or the essence if phenomenology.
