# Surface preservation

Identify the source surface to preserve semantics, not to reroute the enhancement itself.

| Surface/context | Typical signals | Preserve during enhancement |
|---|---|---|
| Task/session prompt | one bounded objective or session brief | requested outcome, inputs, constraints, acceptance/output contract |
| Agent definition | durable identity, authority, tools, escalation | responsibility, authority model, permission envelope, durable behavior |
| API/template prompt | application-managed messages, variables, schemas, request binding | variable names, role/message boundaries, structured-output contract, provider requirements |
| Delegation contract | assigned worker task plus return/evidence/stop contract | delegated authority, ownership, return evidence, stop/escalation conditions |
| Reusable action | repeated procedure, manual/model-selected activation, reusable resources | activation mode, arguments, permissions, resource bindings |
| Persistent instruction | repository/workspace/path-scoped durable rules | scope, precedence, host-native placement semantics, persistent constraints |
| Router/evaluator/linter | classification or evaluation criteria | decision taxonomy, precedence, evidence/rubric rules, non-generation boundary |
| Handoff/execution prompt | context transfer to another session/agent | settled decisions, source references, open assumptions, continuation objective |
| Other/free-form | no formal suite surface or a domain-specific surface | the source artifact's own identity and explicit contract |

Subject matter is not a surface. A prompt about APIs is not automatically an API-template prompt; a prompt about agents is not automatically an agent definition. UI, research, coding, writing, analysis, and other domains remain domains unless the artifact itself has a formal prompt surface.
