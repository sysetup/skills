# Task and session prompts

Frame a single objective or bounded set of related outcomes. Separate supplied facts from assumptions and requested work. Identify necessary source data, permissions, constraints, non-goals and expected result. Do not perform the underlying task merely because its source prompt asks for it.

Use a compact paragraph for simple tasks and explicit input/output/verification sections for complex ones. Avoid over-specification, long generic checklists and invented persona credentials. A session instruction applies only for the declared session; do not silently install it persistently.

Useful patterns: summarize notes into decisions, actions and unresolved items; extract facts with explicit missing-value behavior; investigate an issue with reproducible observations and uncertainty; implement a bounded change with repository-derived test commands; evaluate an artifact against an explicit rubric. Topic profiles add requirements, not new surfaces.

Keep untrusted source material clearly separated. Ask only for blocking missing context. For safe under-specified requests, provide a provisional prompt with assumptions rather than inventing facts. Approval and verification language must match actual permissions and available tools.

Completion: a paste-ready prompt, concise material-change notes when editing, and static/behavioral status. Do not wrap a simple task in invented universal frontmatter or force a separate report when the user only needs the prompt.
