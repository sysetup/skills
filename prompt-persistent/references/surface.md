# Persistent instructions

Inspect the repository facts, active instruction files, their actual scope and consumers before editing. Treat filenames as adapter facts; do not assume every host uses AGENTS.md or that every nearest file overrides its parents. Read the chosen adapter's discovery and precedence notes.

Extract universal essentials: purpose, verified commands, boundaries, conventions that change execution and done criteria. Put task-specific evidence and transient user payloads elsewhere. Link detailed references only when they ship or exist at a verified project path, and explain when to load them. Do not impose a universal line quota or number of files.

For consolidation or explicitly structural refactoring, create a source-to-destination coverage ledger before moving content. Record each material source rule as retained, moved, merged with an equivalent rule, or intentionally removed with evidence; unresolved contradictions stay explicit. Preserve existing restrictions, safety intent, authority, scope, non-goals, and semantic coverage. Remove obsolete material only with evidence, and remove duplicates only when their meaning and scope are equivalent. Keep meaningful secret-handling guards even when they appear obvious. Apply scope reductions explicitly; never broaden a nested rule to the whole workspace accidentally.

Do not use consolidation to improve effectiveness, reliability, precision, or behavior. Those are semantic enhancement goals owned by `prompt-enhance`. A bare `refactor` request is therefore enhancement unless the user clearly constrains it to structural compaction/reorganization with no semantic modification.

Native metadata is host-specific. Plain AGENTS.md has no required YAML. Toolkit identity, provenance and validation belong beside it, not in invented frontmatter. Examples of build/test commands from a source skill are illustrative until repository configuration verifies them.

Completion: deliver clean native file(s), a scope/discovery explanation tied to the adapter, a coverage/change ledger for edits, and verification status. Do not execute repository commands or install files unless that action is authorized.
